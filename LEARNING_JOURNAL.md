### [2026-08-08] Этап 0: Завершение Главы 5 — if Statements (часть 2)
- **Изучено (Python/ML):**
  - **Несколько `elif` блоков:** каждый `elif` проверяет отдельное условие, Python выполняет **первый** истинный блок. Порядок условий важен — сверху вниз.
  - **Пропуск блока `else`:** блок `else` не обязателен; можно писать только явные условия. Если все условия ложны и `else` нет — код просто пропускается.
  - **Проверка нескольких условий:** последовательные `if` блоки проверяют все условия независимо (в отличие от `if-elif-else`, где срабатывает только первый).
  - **Проверка особых элементов в цикле:** комбинация `for` + `if` для поэлементной валидации списка — основа обработки данных в пайплайнах.
  - **Проверка, что список не пустой:** `if list_name:` использует истинность списка (пустой = `False`, непустой = `True`). Не нужно `len()` или сравнение с `[]`.
- **Связь с ML/AI (Зачем это нужно):**
  - **Несколько `elif`** — градация уровней важности в мониторинге: `critical` → стоп пайплайн, `error` → алерт дежурному, `warning` → запись в лог (Huyen DMLS, Ch. 7 — monitoring & alerting).
  - **Пропуск `else`** — обработка только известных значений: если статус модели не в whitelist (`ready`, `training`, `failed`) — код ничего не делает, а не пытается обработать неизвестное (McMahon Ch. 5 — deployment gates).
  - **Последовательные `if`** — мульти-критериальная валидация: проверка accuracy, latency, memory usage — каждый критерий оценивается независимо, все должны пройти (Huyen DMLS, Ch. 3 — data validation).
  - **`for` + `if`** — поэлементная фильтрация данных: цикл проходит по каждому значению датасета, условие определяет — принять, пометить как выброс или отбросить (Huyen DMLS, Ch. 3 — data preprocessing).
  - **`if list_name:`** — проверка наличия данных перед обработкой: "если батч пуст — пропустить итерацию", "если список предсказаний пуст — не запускать агрегацию метрик" (McMahon Ch. 3 — training pipelines).

### [2026-08-08] Этап 0: Освоение условных инструкций (Matthes Глава 5 — часть 1)
- **Изучено (Python/ML):**
  - **Операторы сравнения:** `==`, `!=`, `>`, `<`, `>=`, `<=` — основа всех условных проверок в коде.
  - **Проверка равенства строк:** чувствительность к регистру, сравнение `==` вне `if` (возвращает `True`/`False` как обычное значение).
  - **Игнорирование регистра:** метод `.lower()` для приведения строк к единому виду перед сравнением. Строки в Python **неизменяемы** — `.lower()` создаёт новую строку.
  - **Логические операторы:** `and` (строгий привратник — нужны все условия), `or` (мягкий — достаточно одного).
  - **Операторы принадлежности:** `in` и `not in` — проверка наличия/отсутствия элемента в списке (работают также со строками и словарями).
  - **Булевы выражения:** сохранение результата сравнения (`True`/`False`) в переменную (`bool`) для повторного использования.
  - **Три паттерна условных инструкций:**
    - Простой `if` без `else` — осознанный пропуск действия (side-effects: логирование, алерты).
    - `if-else` — обязательное ветвление (маршрутизация пайплайна: деплой или переобучение).
    - `if-elif-else` — многоуровневая маршрутизация (выбор действия из нескольких вариантов).
- **Связь с ML/AI (Зачем это нужно):**
  - **`==` / `!=`** — сравнение предсказанных меток с истинными (основа расчёта accuracy), проверка статусов пайплайна (`status == "completed"`), валидация форматов данных.
  - **`.lower()`** — стандартная техника очистки текстовых данных (NLP): приведение к единому регистру перед токенизацией и векторизацией (Huyen DMLS, Ch. 3 — data preprocessing).
  - **`and` / `or`** — основа quality gates в CI/CD: деплой только если `accuracy >= target AND latency <= threshold`; переобучение если `accuracy < target OR drift_detected` (McMahon Ch. 5, Gift Ch. 5 — monitoring).
  - **`in` / `not in`** — whitelist/blacklist фильтрация: валидация категориальных признаков, проверка класса ∈ допустимому набору, guardrails в LLM-системах (Iusztin Ch. 8 — safety).
  - **Boolean-флаги** (`is_ready`, `has_error`, `is_validated`) — стандартный паттерн управления потоком в ML-пайплайнах: вычислить один раз, использовать везде.
  - **`if-elif-else`** — многоуровневая маршрутизация моделей: `accuracy >= 95 → деплой`, `>= 90 → дообучение`, иначе → полный ретрейн (McMahon Ch. 5 — deployment gates).

### [2026-08-02] Этап 0: Списки, циклы, range() + первый push на GitHub
- **Изучено (Python/ML):**
  - **Списки (Lists):** создание `[]`, индексация (включая отрицательную `-1`), модификация по индексу.
  - **Операции со списками:** добавление (`.append()`, `.insert()`), удаление (`del` как оператор языка, `.pop()` с возвратом значения, `.remove()` по значению).
  - **Организация списков:** постоянная сортировка (`.sort()`), временная безопасная сортировка (`sorted()`), обратный порядок (`.reverse()`), получение длины (`len()`).
  - **Циклы:** перебор элементов через `for`, критическая важность отступов (IndentationError, TabError) для определения блоков кода.
  - **Числовые последовательности:** функция `range(start, stop, step)`, понимание того, что `stop` не включается, использование отрицательного шага. Преобразование ленивого итератора `range` в полноценный список через `list()`.
  - **Разница `range` vs `list`:** `range` — ленивый (экономит RAM), `list` — в памяти (поддерживает все методы).
- **Связь с ML/AI (Зачем это нужно):**
  - **Списки и циклы** — абсолютная основа для итерации по признакам (features) при масштабировании, перебора списка моделей для кросс-валидации, построчной обработки датасетов.
  - **`del` vs `.pop()` vs `.remove()`:** разные сценарии в ML-пайплайнах: `del` для удаления некорректного столбца-признака, `.pop()` для извлечения и использования последней модели из очереди инференса, `.remove()` для очистки конфига от устаревших параметров.
  - **`.sort()` vs `sorted()`:** правило большого пальца — если не уверены, используйте `sorted()` (безопаснее, не мутирует исходный датасет).
  - **`len()`** — критично для проверки размера датасета, количества признаков, размера батча перед подачей в модель.
  - **`range` vs `list(range)`:** `range` критически важен для экономии RAM при генерации миллионов индексов эпох или батчей. `list(range())` необходим, когда требуется индексация, взятие срезов (slicing) или передача коллекции в функции sklearn/pandas.
