### [2026-08-16] Этап 0: Завершение Главы 10 — Files and Exceptions (Файлы и исключения)
- **Изучено (Python/ML):**
  - **Чтение файлов целиком:** метод `.read()` возвращает всё содержимое файла как одну строку. Конструкция `with open(...) as file_object:` автоматически закрывает файл после выхода из блока с отступом.
  - **Пути к файлам через `pathlib`:** модуль `Path` создаёт кроссплатформенные пути, которые автоматически подстраиваются под Windows (`\`) или Linux/Mac (`/`). Метод `.read_text()` читает файл и сразу закрывает его — современная альтернатива `with open()`.
  - **Чтение файла построчно:** метод `.readlines()` возвращает список, где каждый элемент — одна строка файла с символом переноса `\n` на конце.
  - **Обработка содержимого файла:** сборка нескольких строк в одну через `+=` и `strip()`, подсчёт длины через `len()`, срезы для получения первых N символов.
  - **Запись в файл (режим `'w'`):** метод `.write()` записывает строку в файл. Если файл существует, его содержимое **удаляется**. Метод не добавляет перенос строки автоматически.
  - **Запись нескольких строк:** явное добавление символа `\n` в конец каждой строки при записи.
  - **Добавление в файл (режим `'a'`):** append-режим дописывает новые данные в конец файла, сохраняя старое содержимое.
  - **Обработка исключений `try-except`:** блок `try` содержит код, который может вызвать ошибку. Если ошибка возникает, Python переходит в соответствующий блок `except`, и программа не падает.
  - **Типы ошибок:** `ZeroDivisionError` (деление на ноль), `FileNotFoundError` (файл не найден).
  - **Молчаливая обработка ошибок:** оператор `pass` внутри `except` говорит Python «ничего не делать, продолжай дальше». Программа игнорирует ошибку.
  - **Анализ текста:** метод `.split()` разбивает строку на список слов по пробелам. Метод `.count()` считает количество вхождений подстроки.
  - **Работа с несколькими файлами:** вынесение повторяющегося кода в функцию и вызов её в цикле для обработки списка файлов. Если один файл отсутствует, программа продолжает работу с остальными.
  - **Формат JSON:** модуль `json` для сохранения и загрузки данных Python в универсальном текстовом формате. Функция `json.dump(data, file)` сохраняет объект (список, словарь), `json.load(file)` загружает его обратно.
  - **Рефакторинг:** разбиение длинного кода на несколько чистых функций, каждая из которых делает одно простое дело (например, `get_stored_username()`, `get_new_username()`, `greet_user()`).
  - **Проверка существования файла:** метод `path.exists()` возвращает `True` или `False`, помогая избежать ошибки `FileNotFoundError`.
- **Связь с ML/AI (Зачем это нужно):**
  - **Чтение файлов и `pathlib`** — основа загрузки датасетов (наборов данных) и конфигов (файлов с настройками модели). `pathlib` защищает код от ошибок при переносе между Windows и Linux-серверами.
  - **Режим `'a'` (append)** — стандарт для логирования обучения: каждая эпоха (полный прогон модели по данным) дописывает новую строку в лог-файл, не удаляя историю.
  - **`try-except` для устойчивости пайплайнов (последовательностей шагов):** ML-пайплайн не должен падать из-за одного отсутствующего файла с данными или деления на ноль при расчёте метрики (числовой оценки качества модели), если в проверочной выборке нет примеров нужного класса (McMahon Ch. 4 — exception handling).
  - **`pass` для ожидаемых ситуаций:** при обработке сотен файлов датасета отсутствие одного из них может быть штатной ситуацией. `pass` позволяет не засорять логи (журналы событий) лишними сообщениями об ошибках.
  - **JSON как стандарт для конфигов моделей:** все ML-библиотеки (sklearn, PyTorch, transformers) принимают гиперпараметры (настройки до обучения) в виде словарей, которые сохраняются в `.json` файлы. Это позволяет версионировать настройки и делиться ими с командой.
  - **Рефакторинг для тестируемости:** разбиение кода на маленькие функции (`load_data()`, `train_model()`, `evaluate()`) позволяет покрывать каждую функцию unit-тестами (глава 11) и переиспользовать их в разных экспериментах.

- **Изучено (Python/ML):**
  - **Наследование (Inheritance):** создание дочерних классов на основе родительских. Вызов `super().__init__()` для инициализации атрибутов родителя.
  - **Переопределение методов (Overriding):** замена логики родительского метода в наследнике. MRO (Method Resolution Order) — Python ищет метод сначала в классе самого объекта, затем поднимается вверх по иерархии.
  - **Расширение через `super()`:** вызов родительского метода внутри переопределённого метода наследника для добавления новой логики без дублирования кода.
  - **Композиция (Instances as Attributes):** использование экземпляра одного класса как атрибута другого (отношение «имеет», а не «является»).
  - **Моделирование (Modeling):** 4 вопроса проектирования (объекты, атрибуты, методы, связи). Золотое правило: «Предпочитай композицию наследованию».
  - **Импорт классов:** 5 способов. Явные импорты (`from module import Class`) и импорт модуля (`import module`) — стандарт. `from module import *` — антипаттерн (засоряет пространство имён, скрывает происхождение классов).
  - **Модуль `random` (стандартная библиотека):** `randint()` (диапазон), `choice()` (один элемент), `sample()` (несколько уникальных элементов).
  - **Воспроизводимость (Reproducibility):** фиксация зерна генератора через `random.seed(42)` для получения детерминированных (одинаковых при каждом запуске) псевдослучайных последовательностей.
  - **List Comprehension с условием:** `[x for x in seq if condition]` — компактная фильтрация списков.
  - **PEP 8 для классов:** CamelCase для имён классов, snake_case для методов/атрибутов/экземпляров. Обязательные docstrings для классов и методов.
- **Связь с ML/AI (Зачем это нужно):**
  - **Наследование** — фундамент ML-фреймворков. В scikit-learn все модели наследуются от `BaseEstimator`, в PyTorch нейросети наследуются от `nn.Module`. Это позволяет переопределять `forward()` или `fit()`, сохраняя общий интерфейс.
  - **Композиция** — основной способ сборки сложных ML-систем (Huyen DMLS, Ch. 1). Пайплайн (Pipeline) *содержит* предобработчики и модель; эксперимент (TrainingRun) *содержит* датасет, оптимизатор и конфиг.
  - **Модули** — структура продакшн ML-проектов (McMahon Ch. 1). Классы моделей, метрик и датасетов выносятся в отдельные файлы (`models.py`, `metrics.py`, `data.py`), а основной скрипт только импортирует их.
  - **`random.seed()`** — абсолютное требование для воспроизводимости экспериментов (Huyen DMLS, Ch. 2). Без фиксации seed невозможно сравнить две модели, отладить баг или повторить чужой результат.
  - **List Comprehension с фильтром** — стандарт для предобработки данных: фильтрация выбросов, отбор признаков, разделение датасета на train/test индексы.
  - **PEP 8 и docstrings** — стандарт индустрии. В команде ML-инженеров код читают чаще, чем пишут. Docstrings автоматически превращаются в документацию API.

### [2026-08-15] Этап 0: Начало Главы 9 — Classes (Классы, секции 9.1–9.2)
- **Изучено (Python/ML):**
  - **Классы как шаблоны:** инструкция `class Dog:` создаёт шаблон для будущих объектов. Имена классов пишутся в CamelCase (отличие от snake_case переменных).
  - **Метод `__init__()` (конструктор):** специальный метод, который Python вызывает **автоматически** при создании каждого нового объекта. В нём инициализируются атрибуты объекта.
  - **Параметр `self`:** обязательный первый параметр методов класса. Это ссылка на сам создаваемый объект, даёт ему доступ к собственным атрибутам и методам. Python подставляет `self` автоматически при вызове метода.
  - **Атрибуты экземпляра (`self.name = name`):** переменные, которые привязаны к конкретному объекту. У каждого экземпляра свой независимый набор атрибутов.
  - **Инстанцирование (`my_car = Car("audi", "a4", 2024)`):** процесс создания объекта из класса. Python создаёт пустой объект, вызывает `__init__` с переданными аргументами и возвращает готовый экземпляр.
  - **Доступ к атрибутам через точку:** `config.learning_rate`, `my_car.odometer_reading`. Атрибуты можно использовать в переменных, условиях, выражениях — как обычные переменные.
  - **Методы с `return`:** методы класса могут **возвращать** значение вызывающему коду, а не только печатать его. В продакшене почти всегда используется `return` для дальнейшей обработки результата.
  - **Атрибуты со значением по умолчанию:** создаются внутри `__init__` без внешнего параметра (`self.odometer_reading = 0`). Каждый экземпляр получает их автоматически.
  - **Три способа изменения атрибутов:**
    - **Прямое присваивание** (`my_car.attr = 23`) — быстро, но без валидации.
    - **Через метод-обёртку** (`update_odometer(value)`) — можно добавить проверку значения перед записью.
    - **Инкремент через метод** (`increment_odometer(miles)` с оператором `+=`) — для увеличения значения на заданную величину.
  - **Множественные независимые экземпляры:** от одного класса можно создать сколько угодно объектов. Каждый хранит свои атрибуты изолированно, изменение одного не влияет на другие.
- **Связь с ML/AI (Зачем это нужно):**
  - **Классы — основа ML-фреймворков.** Scikit-learn, PyTorch, TensorFlow построены на классах: `LogisticRegression()`, `nn.Module`. Каждый эксперимент или модель — это экземпляр класса со своими настройками.
  - **`__init__` для гиперпараметров (настроек модели до обучения):** `ModelConfig(algorithm="SGD", learning_rate=0.01, epochs=50)`. Все гиперпараметры инициализируются один раз при создании конфига и используются на всех этапах пайплайна.
  - **Атрибуты по умолчанию для внутреннего состояния:** счётчик эпох `self.current_epoch = 0`, флаг обучения `self.is_training = True`, буфер предсказаний `self.predictions = []`. Начинаются с нуля и меняются по ходу работы модели.
  - **Методы-обёртки для безопасной смены гиперпараметров:** `model.set_learning_rate(0.001)` с проверкой, что значение положительное. Защита от некорректных настроек в продакшене.
  - **Инкремент для счётчиков:** `self.current_epoch += 1` после каждой эпохи (полного прогона по данным), `self.step_count += batch_size` — стандартный паттерн в training loops.
  - **Несколько экземпляров для сравнения моделей:** `baseline = ModelConfig("LR", 0.01)`, `candidate = ModelConfig("RF", 0.1)` — каждый хранит свои настройки независимо для A/B тестирования и подбора гиперпараметров.
  - **Методы с `return` для генерации артефактов:** `model.get_descriptive_name()` возвращает строку для имени файла сохранённой модели или лога эксперимента в системе трекинга (MLflow, Weights & Biases).

### [2026-08-13] Этап 0: Завершение Главы 8 — Functions (Функции)
- **Изучено (Python/ML):**
  - Определение функции через `def` с указанием типа возвращаемого значения (`-> None`, `-> float`, `-> dict[str, float]`, `-> list[float]`).
  - Различие **параметров** (переменные при объявлении функции) и **аргументов** (реальные значения при вызове).
  - Четыре способа передачи аргументов: позиционные (порядок важен), именованные (порядок не важен, лучше читаемость), значения по умолчанию, комбинация позиционных и именованных.
  - Оператор `return` — возврат значения из функции (в отличие от `print`, который только показывает на экране).
  - Паттерн **«необязательный аргумент»**: использование дефолта `""` как маркера отсутствия, проверка `if param != ""` внутри функции.
  - Паттерн **«аккумулятор»**: создание пустого списка `[]` и наполнение его через `.append()` в цикле для сбора результатов фильтрации.
  - Передача списка в функцию: чтение элементов, возврат отфильтрованных данных.
  - **Критически важное поведение — передача по ссылке:** изменения списка внутри функции (через `.pop()`, `.append()`) **сохраняются** в оригинале после завершения функции.
  - **Защита списка от изменений** через срез `[:]` — создание копии, чтобы оригинал остался нетронутым.
  - **`*args` (произвольные позиционные аргументы):** звёздочка `*` собирает все переданные аргументы в **кортеж** (неизменяемую коллекцию). Это защита: кортеж нельзя случайно изменить внутри функции.
  - **`**kwargs` (произвольные именованные аргументы):** двойная звёздочка `**` собирает именованные аргументы в **словарь**. Словарь создаётся заново при каждом вызове — он локальный, снаружи его не существует, поэтому защита не нужна.
  - Смешивание позиционных и произвольных аргументов: обязательные параметры всегда идут до `*args` и `**kwargs`.
  - Чтение `TypeError` в Traceback — определение, пропущен аргумент или передан лишний.
- **Связь с ML/AI (Зачем это нужно):**
  - **Функции — основа модульного ML-кода.** Каждый этап пайплайна (последовательности шагов обработки данных) выделяется в отдельную функцию: `load_data()`, `preprocess()`, `train_model()`, `evaluate()`. Это делает код читаемым, тестируемым и переиспользуемым (McMahon Ch. 1 — project structure).
  - **Возврат метрик из функции оценки:** `evaluate_model()` возвращает словарь `{"accuracy": 0.95, "f1": 0.93}` за один вызов, а не печатает значения (Huyen DMLS, Ch. 2 — experiment tracking).
  - **Защита исходных данных через `[:]`:** стандартный паттерн при предобработке. Функция работает с копией датасета, оригинал остаётся для повторных экспериментов и анализа «до/после».
  - **`*args` для переменного числа признаков (features):** функция `train_model("RandomForest", "возраст", "доход", "город")` может принимать от 1 до бесконечности признаков без изменения кода (McMahon Ch. 3 — feature engineering).
  - **`**kwargs` для гибкой настройки гиперпараметров:** функция `configure_experiment(model, lr=0.01, epochs=100, dropout=0.2)` принимает любое количество настроек. Это основа API всех ML-библиотек (sklearn, PyTorch, Hugging Face transformers).
  - **Паттерн «необязательный аргумент»:** используется для параметров, которые есть не всегда (например, `experiment_id`, `checkpoint_path`). Функция работает и с полными, и с частичными настройками.
  - **Паттерн «аккумулятор»:** фильтрация предсказаний с уверенностью выше порога, отбор признаков по критерию важности, сбор только валидных примеров датасета.

### [2026-08-12] Этап 0: Завершение Главы 7 — User Input и while-циклы
- **Изучено (Python/ML):**
  - Функция `input()` — блокирующая функция, приостанавливающая программу до ввода пользователя. Последовательное выполнение кода (sequential execution).
  - Преобразование строки в число: `int()` для числового ввода (input всегда возвращает строку).

  - Три паттерна управления `while`: проверка значения (`while msg != "quit"`), флаг (`while active`), бесконечный цикл (`while True` + `break`).
  - `break` — немедленный выход из цикла, `continue` — пропуск текущей итерации без завершения цикла.
  - Бесконечные циклы: типовые ошибки (забытый инкремент), остановка через `Ctrl+C`.
  - `while list:` + `pop()` — перемещение элементов между списками (стек LIFO).
  - `while x in list:` + `remove()` — удаление всех вхождений значения.
  - Заполнение словаря в цикле: `dict[key] = value` при вводе от пользователя.
- **Связь с ML/AI (Зачем это нужно):**
  - `input()` + `int()` — получение числовых параметров от пользователя: количество эпох (полных прогонов модели по данным), размер батча (пакета данных).
  - `%` — работа с батчами (остаток от деления размера датасета на batch_size), логирование метрик каждые N эпох.
  - `while` — итеративные процессы: обучение модели до достижения порога ошибки, сбор данных до команды остановки.
  - Флаги (`bool`) — управление режимами пайплайнов (последовательностей шагов): `is_training`, `is_inference` (применение модели к новым данным).
  - `break` — прерывание перебора гиперпараметров или поиска в данных при достижении условия.
  - `continue` — фильтрация невалидных данных в пайплайне: пропуск примеров с пропущенными значениями или аномалиями.
  - Перемещение между списками — передача данных между этапами пайплайна (raw → validated → train).
  - Заполнение словаря из ввода — сбор гиперпараметров (настроек модели) в конфиг (файл или структуру с настройками).

  - **`if list_name:`** — проверка наличия данных перед обработкой: "если батч пуст — пропустить итерацию", "если список предсказаний пуст — не запускать агрегацию метрик" (McMahon Ch. 3 — training pipelines).
