# 🔧 Git Workflow: Правила атомарных коммитов

## 📌 Золотое правило
**Один логический блок изменений = один коммит**

## 🎯 Когда делать коммит
После завершения каждой логической единицы работы:
- ✅ Завершена подглава книги (например, Matthes 3.1-3.2)
- ✅ Написан и протестирован учебный скрипт
- ✅ Добавлена новая функция/модуль в `src/`
- ✅ Написаны тесты для новой функциональности
- ✅ Исправлена ошибка (bugfix)
- ✅ Обновлена документация (README, docstrings)
- ✅ Изменена конфигурация (requirements.txt, .gitignore)

## 📝 Формат сообщений коммитов (Conventional Commits)

<тип>(<область>): <краткое описание>

[опциональное тело коммита]

[опциональные ссылки]

### Типы коммитов:
- `feat` — новая функциональность
- `fix` — исправление ошибки
- `docs` — изменения в документации
- `style` — форматирование, пробелы (без изменения кода)
- `refactor` — рефакторинг кода (без изменения функциональности)
- `test` — добавление/изменение тестов
- `chore` — рутинные задачи (обновление зависимостей, конфигурации)

### Примеры:
- feat(python): add list sorting methods (Matthes 3.3.1-3.3.2)
- fix(data): handle missing values in feature engineering
- docs(readme): update installation instructions
- test(classifier): add unit tests for wine classifier
- chore(deps): update scikit-learn to 1.3.0

## 🚫 Когда НЕ делать коммит
- ❌ В процессе написания кода (незавершённая функция)
- ❌ С накоплением изменений за несколько дней/недель
- ❌ С сообщением "update" или "fix" без конкретики
- ❌ Без проверки, что код работает (pytest, manual test)

## 🔄 Процесс коммита
1. Проверить статус: `git status`
2. Добавить изменения: `git add <файлы>` или `git add .`
3. Сделать коммит: `git commit -m "тип(область): описание"`
4. Проверить историю: `git log --oneline -5`

## 📊 Частота коммитов
**Минимум:** 1 коммит на микро-шаг курса (после подтверждения "готово")
**Оптимально:** 1 коммит на подглаву книги или логический блок кода
**Максимум:** Не накапливать изменения дольше 1 дня работы

## 🎓 Для учебных проектов
После каждого микро-шага курса:
1. Убедиться, что код работает
2. Сделать коммит с указанием главы/подглавы
3. Обновить `project_state.md` (если нужно)
4. Продолжить к следующему шагу
