# 📖 Словарь терминов (GLOSSARY)

Централизованный словарь ML/AI-терминов, встречающихся в курсе.
Единственный источник истины для определений (принцип SSOT).

## Как обновлять

При появлении нового ML-термина в микро-шаге:
1. Ментор расшифровывает термин в скобках прямо в тексте шага.
2. Ментор указывает: «Новые термины для GLOSSARY.md: ...».
3. Термины можно добавлять сразу или накапливать в течение сессии.
4. Перед добавлением проверяем, нет ли уже такого термина. Если термин уже есть — не добавляем новую строку, а обновляем существующую: уточняем определение или добавляем пример.
5. В конце сессии делаем финальную сверку: добавляем только отсутствующие термины, убираем дубликаты и сортируем таблицу по алфавиту.

## Термины

| Термин (English) | Простое определение | Пример / Контекст |
|---|---|---|
| **Adaptability** (адаптируемость) | Способность системы быстро перестраиваться под изменения в данных или бизнес-логике. | Модель переобучается на свежих данных при обнаружении drift. |
| **Baseline** (Базовая модель) | Простая модель, с которой сравнивают более сложные модели для оценки их реальной пользы. | Модель B (baseline) оказалась лучше для продакшена, чем сложная Model A, из-за скорости и дешевизны. |
| **Бизнес-цель** (Business Objective) | Конечный результат, важный для компании (например, рост прибыли, снижение затрат, удержание клиентов). | "Снизить затраты на логистику на 10%". |
| **Data-driven подход** (Data) | Решение задачи через обучение модели на данных. Модель сама находит закономерности. | Классификатор изображений, обученный на 1 млн фото кошек и собак. |
| **Детерминированный vs Вероятностный** | Детерминированный подход дает точный ответ (Да/Нет). Вероятностный подход (ML) дает оценку уверенности (score), которую мы сравниваем с порогом (threshold). | Традиционный код возвращает просто "Спам". ML-код возвращает "Спам (оценка: 1.3)". |
| **Drift** (дрейф данных) | Изменение распределения входных данных со временем, из-за чего качество модели падает. | После пандемии модель предсказания спроса начала ошибаться из-за изменения поведения покупателей. |
| **Iterative process** (итеративный процесс) | Циклическая разработка ML-системы, где после каждого этапа возможен возврат к предыдущему на основе новых данных или результатов. | После деплоя модель возвращается к этапу сбора данных из-за обнаруженного drift. |
| **Классификация** (Classification) | Тип ML-задачи, где модель относит объект к одной из заранее известных категорий. | Определение, является ли транзакция мошеннической (0 = нормальная, 1 = фрод). |
| **Latency** (Задержка) | Время между запросом и ответом модели. В продакшене часто есть жёсткий лимит (например, не более 100 мс). | Требование бизнеса, чтобы модель предсказывала отток клиента не дольше 50 мс. |
| **Maintainability** (сопровождаемость) | Легкость обновления, мониторинга и передачи системы между инженерами и командами. | ML-пайплайн покрыт тестами, имеет версию модели и документацию в репозитории. |
| **Метка** (Label) | Правильный ответ, который мы хотим, чтобы модель научилась предсказывать на основе признаков. | Слово «Комфортно» — это метка для температуры 15.0. |
| **Метрика** (Metric) | Числовая оценка качества работы ML-модели, которую мы оптимизируем в процессе обучения и отслеживаем в продакшене. | MAE (Средняя абсолютная ошибка), ROC-AUC, Accuracy. |
| **ML-система** (ML System) | Программы, где логика не прописана вручную, а извлечена (обучена) из данных. Вероятностны: выдают оценку уверенности и могут ошибаться. Требуют мониторинга данных. | Фильтр, который суммирует веса слов "купите", "срочно" и "бесплатно", чтобы оценить вероятность спама. |
| **ML-цель** (ML Objective) | Конкретная математическая или алгоритмическая задача, которую решает модель, чтобы помочь достичь бизнес-цели. | "Спрогнозировать точное время доставки заказа". |
| **Модель** (Model) | Результат обучения алгоритма. Функция, которая принимает новые признаки и выдаёт предсказания. | После обучения на исторических данных модель может предсказать, будет ли холодно при температуре -5.0. |
| **Обучение** (Training) | Процесс, в ходе которого алгоритм анализирует исторические данные (признаки и метки) и создаёт модель. | Алгоритм посмотрел на 4 примера температур и меток, и выучил закономерность. |
| **Production-ограничения** | Нефункциональные требования к ML-системе: скорость, стоимость, надёжность, масштабируемость. | Модель с точностью 95% не берут в продакшен, потому что она отвечает 5 секунд (не проходит по latency). |
| **Признак** (Feature) | Входная характеристика объекта (данные), которую мы подаём в программу или модель для анализа и принятия решения. | Температура воздуха 15.0 — признак для предсказания погоды; слова «купите», «срочно», «бесплатно» — признаки для оценки спама. |
| **Регрессия** (Regression) | Тип ML-задачи, где модель предсказывает непрерывное числовое значение. | Предсказание стоимости квартиры (например, 150000.50). |
| **Reliability** (надёжность) | Способность ML-системы корректно работать как на ожидаемых, так и на неожиданных входных данных. | Модель предсказания оттока возвращает валидный ответ даже при пропусках в данных клиента. |
| **Rule-based подход** (Mind) | Решение задачи через явные правила, написанные инженером. Быстро и понятно, но не масштабируется. | Спам-фильтр на ключевых словах: "бесплатно", "выигрыш". |
| **Scalability** (масштабируемость) | Способность системы сохранять качество и скорость работы при росте нагрузки или объёма данных. | Сервис рекомендаций обрабатывает 10 000 запросов в секунду без деградации latency. |
| **Trade-off** (компромисс) | Ситуация, когда улучшение одного параметра ухудшает другой (например, скорость vs качество). | Trade-off между latency (быстрый ответ) и accuracy (точность модели). |
| **Традиционное ПО** (Traditional Software) | Программы, где логика работы жестко задана разработчиком через правила (if/else). Детерминированы: при одних и тех же входных данных всегда выдают один и тот же результат. | Фильтр, который помечает письмо как спам только если в нем есть ТОЧНАЯ фраза "купите бесплатно". |
| **Фрейминг** (Framing) | Процесс перевода абстрактной бизнес-проблемы на язык конкретных ML-задач и метрик. | Перевод задачи "показать лучшие товары" в задачу "ранжирование" (Ranking). |
| **Эвристика** (Heuristic) | Практическое правило или чек-лист для принятия решений, когда точный алгоритм отсутствует. В ML используется для первичной оценки целесообразности задачи. | Чек-лист из 3 пунктов (сложность паттерна, наличие данных, толерантность к ошибкам) для решения, нужен ли здесь ML. |
